## 2. Precondiciones

Sin esto, varios casos van a fallar por configuración y no por código.

- [ ] Correr en el SQL Editor de Supabase, en orden: `usuarios.sql` →
      **`usuarios-acceso-rapido.sql`** → `mesas.sql` → `productos.sql` →
      `pedidos.sql` → `chat.sql` → `notificaciones.sql`.
- [ ] En `notificaciones.sql`, descomentar y completar las dos líneas de
      `ALTER DATABASE` con la URL real del proyecto y la `service_role key`.
- [ ] Extensión `pg_net` habilitada (Database → Extensions).
- [ ] Edge Function desplegada y con la cuenta de servicio cargada:
      ```bash
      supabase functions deploy enviar-notificacion
      supabase secrets set FIREBASE_SERVICE_ACCOUNT="$(cat cuenta-servicio.json)"
      ```
- [ ] APK instalada en un teléfono **físico** (el emulador no entrega push de
      FCM de forma confiable) y permiso de notificaciones aceptado.
- [ ] Un segundo dispositivo o una sesión web para operar el otro rol.
- [ ] Una casilla de correo real para recibir los avisos de EmailJS.

**Consulta que se usa varias veces** (SQL Editor):

```sql
SELECT correo_electronico, estado, token_push
FROM public.usuarios
WHERE correo_electronico LIKE '%@restaurante.com'
ORDER BY correo_electronico;
```

Los 6 tests de `notificaciones.token.spec.ts` cubren el problema del token,
incluido el caso exacto de UAT-03: cerrar sesión y volver a entrar sin reiniciar
la aplicación.

### Sobre los 16 tests que fallan

**No los introdujo este cambio.** Fallan igual en `testing-uat` sin el merge
(comprobado en un worktree del commit anterior: 157 pasaban y fallaban los
mismos 16, por las mismas causas). Son `tarjeta-usuario.component.spec.ts` (15,
por `NG0950: Input is required but no value is available yet`) y un caso de
`formulario-registro.component.spec.ts`.

Tampoco está confirmado que fallen de verdad: en la máquina donde se corrieron,
el builder de Angular no arranca porque la CLI exige Node ≥ 24.15.0 y hay
24.14.0, así que se usó vitest a mano y ese atajo no reproduce todo lo que hace
`@angular/build:unit-test`. **Hay que correr `npm test` en una máquina con Node
24.19** (la del README) para saber si son fallos reales o del atajo.

### Sobre los errores de eslint

Los 8 errores son `@angular-eslint/no-empty-lifecycle-method` y las 2
advertencias son `use-lifecycle-interface`, todos en archivos que esta rama no
toca (`tarjeta-mesa`, `tarjeta-usuario`, `home.page`, `modificar.page`,
`alta-empleado`, `alta-mesa`, `metre-registrar-cliente`). Vienen de `main-test`.
Se arreglan borrando los `ngOnInit() {}` vacíos, pero conviene que lo haga quien
escribió cada pantalla.
